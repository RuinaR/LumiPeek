# LumiPeek

[Little LUMI Model](https://store.steampowered.com/app/5075020/) 사진 감상 플러그인을 개발하는 저장소입니다. Windows 파일 워커·로컬 AI·설정·사진 감상 흐름을 연결한 개발 패키지를 빌드할 수 있습니다. 공식 SDK 1.5.0의 모의 환경에서 검증했으며 실앱용 정식 릴리스는 아닙니다. 기존 꼬미 코드는 변경하지 않습니다.

## 구현된 기능

- Windows x64 고정 로컬 NTFS의 읽기 전용 폴더 등록·탐색·이미지 읽기. 열린 부모 핸들에 상대적으로 접근하고 볼륨·파일 ID를 검증합니다. 원본에 쓰기·수정·삭제 권한을 요청하지 않습니다.
- 링크·정션·재분석 지점·다중 하드링크·오프라인/회수 대상·UNC·네트워크·SUBST 경로 차단. 루트 교체·경쟁·권한 거부·쓰기 경합은 안전하게 실패합니다.
- PNG/JPEG 확장자·헤더·파일 25MiB·30MP 제한. 이미지 디코딩과 최대1024픽셀 메타데이터 제거 PNG 생성은 별도 JVM에서 수행합니다. 호스트는 크기가 검증된 RGB 픽셀을 받으며 이미지를 다시 디코딩하지 않습니다.
- Windows Job Object 워커: 정지 상태 생성→Job 배정→실행, 동시1개, JVM heap128MiB, 프로세스 commit 할당 한도256MiB, Job commit 한도384MiB. 사진 경로는 상속된 익명 메모리로 전달하고 명령행·임시 파일·로그에 넣지 않습니다. 결과 파이프는8MiB로 제한합니다.
- 취소·시간 초과 시 자신이 만든 워커만 종료하고 늦은 결과를 폐기합니다. 종료 확인 실패 시 `CLEANUP_FAILED`로 새 워커를 차단합니다. 자체 핸들·스레드 정리와 결과 버퍼 해제를 검증했습니다.
- 세션 중복 억제·단일 작업 큐·엄격한 감상 JSON 검사. 원본·경로·AI 원문을 공개 로그나 분석 캐시에 저장하지 않습니다.
- 공식 SDK **1.5.0** JAR로 작은 읽기 전용 플러그인을 컴파일하고 `PluginTestKit` 모의 컨텍스트의 시작·종료·재시작·quiet/bubble 조회를 검증했습니다. 실제 앱·Steam 엔진·GUI·Ollama는 실행하지 않았습니다.
- 루프백 전용 Ollama HTTP 어댑터: 버전·설치 모델 조회, 클라우드 비활성/로컬 비전 모델 확인, 정제 PNG의 구조화 감상 요청, 응답64KiB 제한, 취소·기한·단일 요청 관리. 프록시·리다이렉트·클라우드 모델은 거부하고 다운로드/서버 실행은 하지 않습니다. 실제 모델 대신 합성 사진을 받는 가짜 HTTP 서버로 검증했습니다.
- 사진 선택→분석 중→감상 준비→표시→종료의 상태 머신, 세션별 늦은 응답 차단, 거절 시 생략, 이미지 정리. 자체 미리보기의 부드러운 위치 보간·화면 경계·다중 모니터 좌표 계산을 headless로 검증했습니다. 실제 창이나 캐릭터 이동은 생성·조작하지 않습니다.
- `LumiPeek` 서비스 진입점, 트레이·캐릭터 메뉴·설정 버튼, SDK 이벤트와 종료 정리. 수동 감상과 세션별 자동 감상(5~240분), 일시정지, 폴더별 순환 선택, 최근 사진 중복 억제를 연결했습니다. 시작 시 네트워크 요청·모델 로딩·사진 탐색을 하지 않습니다.
- SDK 테마 기반 설정 패널: 폴더 추가·제거, 하위 폴더 검색, 자동 간격, 사진 크기(96~180 논리픽셀), 분석 중 표시, AI 연결 확인·설치 모델 조회·모델 선택, 상태·취소를 제공합니다. 숫자·모델·연출 설정만 자체 prefs에 저장하고 사진 폴더 경로는 메모리에만 유지합니다. 자동 감상과 사진 미리보기는 매 실행 기본 OFF입니다.
- 공식 모델 다운로드 동의 화면과 Ollama pull API의 제한된 NDJSON 진행률·취소·오류 처리를 구현했습니다. 고정된 공식 태그만 허용하며 실제 다운로드는 테스트하지 않았습니다. 오류 레코드로 요청 종료가 확인되면 재시도할 수 있고, 취소·연결 단절·잘못된 응답으로 서버 종료가 불확실하면 추가 분석·다운로드·모델 변경을 차단합니다. 자동 재시도·Ollama 설치·실행은 하지 않습니다.
- 전처리된 RGB로만 작은 사진을 만드는 자체 미리보기와 `···` 렌더러를 구현했습니다. 현재 사용자에게 제공하는 범위는 **명시적으로 켠 설정 창 내부 미리보기**입니다. 같은 사진을 분석부터 감상 종료까지 유지하며 취소·제거·종료 시 이미지 버퍼를 정리합니다.

지원 모델은 [qwen3-vl:2b-instruct](https://ollama.com/library/qwen3-vl:2b-instruct), [4b-instruct](https://ollama.com/library/qwen3-vl:4b-instruct), [8b-instruct](https://ollama.com/library/qwen3-vl:8b-instruct)입니다. 공식 라이브러리 확인 시 예상 다운로드는 각각 약1.9/3.3/6.2GB, 라이선스는 Apache-2.0이며 태그 변경에 따라 크기가 달라질 수 있습니다. 실제 메모리·VRAM 요구량은 다운로드 크기와 다릅니다. 다운로드 전 UI에서 출처·예상 용량·라이선스·저장 비용 안내와 동의를 요구합니다.

## 검증과 제한

Windows NT10.0.26200 x64에서 합성 이미지와 프로젝트 임시 폴더로 검증했습니다. JDK21·25, Windows x64 Release 빌드, Java lint/경고 오류 처리, JNI 검사, MSVC 정적 분석 및 DLL 의존성·테스트 함수 제외 감사를 수행합니다. 테스트용 무한 대기·네이티브 대기·OOM·메모리 할당 실패·과도한 출력·비정상 종료를 포함합니다.

Job Object는 **자원 제한이며 파일·네트워크 권한 보안 샌드박스가 아닙니다**. commit 한도는 물리 RAM/RSS 한도와 다르고 OS 집계 비용도 존재합니다. 커널·필터 드라이버가 종료를 막는 경우의 실시간 종료 보장은 없으며 실패 시 추가 작업을 차단합니다. 실제 OneDrive/SMB, 다른 Windows 환경, 장기 부하, 실앱·다른 모드 호환성은 NOT VERIFIED입니다.

공식 main의 [SDK 메타데이터](https://github.com/studio-lumi-h/little-lumi-sdk/blob/main/sdk.json)는1.5.1이지만, 확인한 [공개 Releases](https://github.com/studio-lumi-h/little-lumi-sdk/releases)는1.5.0까지였습니다. **SDK1.5.1 바이너리·보호된 실행 사본의 native 로딩·실앱 코드 동의 검증은 BLOCKED**입니다. 1.5.0 모의 검사 결과를1.5.1 검증 완료로 간주하지 않습니다.

실제 Ollama 추론·다운로드와 설치형 플러그인의 보호 로딩은 NOT VERIFIED입니다. 사진 전송은 호환되는 `/api/status`에서 `cloud.disabled=true`와 로컬 GGUF 비전 메타데이터를 확인한 경우만 허용합니다. 서버 설정은 바꾸지 않습니다. HTTP 취소는 서버 GPU 작업·다운로드의 즉시 중단 보장이 아니므로,종료가 불확실하면 같은 클래스 로더의 새 클라이언트에서도 해당 루프백 주소의 추론·다운로드·모델 변경을 차단합니다. 앱·클래스 로더 재시작이 서버 종료의 증거는 아닙니다. 재실행 전에 서버 작업이 끝났는지 사용자가 확인해야 합니다. 동시1건 제한은 활성 LumiPeek 세션 내부의 제한이며 다른 API 클라이언트까지 통제하지 않습니다. 이는 신뢰하는 로컬 데몬과의 통신 정책이며 데몬 자체의 네트워크 권한을 격리하지 않습니다.

공유 busy와 데스크톱 미리보기는 **차단** 상태입니다. SDK busy는 최대1회/90초 정책만 분리했고 소유권·안전한 조기 해제는 미확정이므로 호출하지 않습니다. 90초 이후에도 설정 창 내부의 `···`만 표시합니다. 자체 JWindow의 무포커스·non-topmost 구성과 SDK 스냅샷 기반 추적 연결은 코드에 있으나, 클릭 통과·실제 DPI/모니터 배치가 미검증이므로 생성 자체를 거부합니다.

감상 직전 EDT에서 quiet·숨김·기존 말풍선·대기 대사·대상 ID를 재확인합니다. SDK는 원자적 말풍선 소유권을 제공하지 않고 대상이 사라지면 fallback할 수 있어 완전 무충돌을 보장하지 않습니다. 다른 bubble/선택지/클릭/드래그 이벤트가 오면 자체 사진 작업을 보수적으로 종료하며 공유 말풍선을 지우지 않습니다. 이벤트에 발화 소유자가 없으므로 자신의 대사 이벤트에도 미리보기가 일찍 정리될 수 있습니다. 실앱·다른 모드 공존과 같은 사진의 전체 표시 시간은 NOT VERIFIED입니다.

짧은 한국어·구체적 관찰·그림/실사 구분을 프롬프트에 지정하고 컨텍스트4096·출력256토큰·작은 배치를 사용합니다. 실제 모델의 환각·반복·범주별 품질·성인 입력 능력은 평가하지 않았습니다. `safeToShow`는 독립적인 콘텐츠 안전 판정이 아닙니다. 공개판 성인 AI 반응은 활성화하지 않으며 일반 사진 감상 범위만 제공합니다.

## 개발 검사

Java 코어에는 JDK17 이상과 PowerShell, Windows 검사에는 x64 MSVC Build Tools/Windows SDK가 필요합니다. SDK 검사에는 JDK25와 사용자가 지정한 공식 배포본이 필요합니다. 스크립트는 SDK·JDK·모델을 자동 다운로드하거나 실제 앱을 실행하지 않습니다.

```powershell
./scripts/test.ps1 -JdkHome '설치된 JDK 경로'
./scripts/test.ps1 -JdkHome '설치된 JDK 경로' -WindowsBoundary
./scripts/build-native.ps1 -JdkHome '설치된 JDK 경로' -Analyze
./scripts/test-sdk.ps1 -SdkHome '공식 SDK 1.5.0 경로' -JdkHome 'JDK25 경로' -ExpectedSdk 1.5.0
./scripts/build-plugin.ps1 -SdkHome '공식 SDK 1.5.0 경로' -JdkHome 'JDK25 경로' -ExpectedSdk 1.5.0
# 출력된 개발 패키지 경로로 실제 워커까지 합성 통합 검사:
./scripts/test-sdk.ps1 -SdkHome '공식 SDK 1.5.0 경로' -JdkHome 'JDK25 경로' -ExpectedSdk 1.5.0 -PluginPackage 'build/plugin-.../LumiPeek'
./scripts/audit.ps1
```

검사는 합성 데이터만 사용하며 산출물·SDK·개인 파일·내부 기록은 Git에서 제외합니다. 실제 게임이나 다른 프로그램의 프로세스·메모리·화면·입력에 접근하지 않습니다. 화면 캡처·전역 후킹·입력 자동화·DLL 주입을 구현하지 않습니다.

개발 패키지는 `build/plugin-.../LumiPeek`에 자체 JAR과 Release DLL만 생성합니다. SDK/JDK를 재배포하거나 앱의 mods 폴더에 자동 설치하지 않습니다. 공식 SDK가 만든 보호 실행 사본의 JAR 옆 `native/` 배치를 사용하고, 원본 설치 JAR 경로를 실행 경로라고 가정하지 않습니다. 현재 검사는 이 배치를 합성으로 재현한 것이며 실제 Steam 코드 동의·재동의·보호 로딩 검증을 대체하지 않습니다.
